# 요소별 특화 — 선택지·질문 제시

사용자에게 결정을 물을 때(AskUserQuestion, 갈림길 제시 등). 사용자는 내 작업 맥락을 모른 채
이 화면만 본다. 여기서 내부 용어가 새면 질문 자체가 이해 불가가 된다.

핵심 한 줄: **질문엔 결정만, 설명엔 사용자가 겪을 결과만.**

---

## Q1. 질문에서 내부 맥락을 걷어낸다

왜 이 질문이 나왔는지(충돌 번호, 누가 지적했는지, 현재 문구)는 대개 필요 없다. 물어보는
것만 남긴다.

```
✗ [충돌 A] OCR 품질 게이트를 어떻게 처리할까요?
  (현재: 'acceptable verbatim quality' — 측정 불가 지적)

✓ AI가 손글씨를 잘 읽는지 언제 확인할까요?
```

## Q2. 설명은 메커니즘이 아니라 결과로

"어떻게 구현되는가"가 아니라 "고르면 뭐가 좋아지고 나빠지나".

```
✗ Page.text가 페이지별 토글을 구조적으로 지원, 필드 수 순감소
✓ 페이지별 사진↔글자 전환이 자연스럽고 나중에 버그 덜 남

✗ auth_provider, 푸시 상태 필드를 현재 구조에 추가
✓ 로그인 종류(애플/카카오) 필드 정도만 보충
```

> **주의**: 여기서 `Team/User/Letter/Page` → `팀/사용자/편지/페이지`로 바꾼 건, 아직 코드에
> 없는 **제안 단계의 이름**이라 좌표가 아니기 때문이다. 이미 구현된 식별자
> (`Page.text`, `getMissionBusinessDate`)는 선택지 안에서도 **그대로 쓴다** → SKILL.md 1-4 ①.

## Q3. 라벨은 짧은 우리말 동사구로

```
✗ 4엔티티 재구조화 / 플랫 유지 + QA 필드 추가 / Leave unchanged / (Recommended)
✓ 4개로 나누기   / 지금 구조 유지 + 빠진 것만 추가 / 그대로 둘래  / (추천)
```

## Q4. 안 고를 선택지는 넣지 않는다

옵션을 억지로 4개까지 채우지 않는다. 실제 갈림길이 둘이면 둘만 낸다.

- `하나씩 검토` 같은 메타 옵션은 실익이 있을 때만. (2건짜리 결정에선 뺀다.)
- `Leave unchanged` / `그대로 둘래`는 사용자가 실제로 안 고칠 수 있을 때만 남긴다.

## Q5. 그럴듯한 함정은 한 줄로 짚는다

정밀해 보이지만 비용이 큰 안은 트레이드오프를 솔직히 적는다. 관용구가 잘 먹는다.

```
✗ 정량 루브릭 — 단, 정답 전사를 직접 타이핑해야 함 (4개 소스가 반대)
✓ 정밀해 보이지만, 재려면 편지를 직접 다 타이핑해야 해서 배보다 배꼽이 큼
```

## 통짜 예시

**✗ 1차:**
```
질문: [충돌 B] 온톨로지를 어떻게 고칠까요? (QA: auth_provider·푸시 필드 누락 지적)
- 4엔티티 재구조화 (Recommended)
  Team/User/Letter/Page로 재편성 — cat_stage·uploader_id·ocr_status는 파생값이라 삭제,
  Page.text가 페이지별 토글을 구조적으로 지원, 필드 수 순감소
- 플랫 유지 + QA 필드 추가
- 최소 변경 — opened_at 타임스탬프 하나만 추가 (simplifier안)
- Leave unchanged
```

**✓ 2차:**
```
질문: 데이터 구조를 정리할까요?
- 4개로 나누기 (추천)
  팀/사용자/편지/페이지로 분리 — 페이지별 사진↔글자 전환이 자연스럽고 나중에 버그 덜 남
- 지금 구조 유지 + 빠진 것만 추가
  로그인 종류(애플/카카오) 필드 정도만 보충
- 그대로 둘래
```

바뀐 것: 충돌 번호·QA 출처 삭제 / 내부 용어(온톨로지·엔티티·파생값·simplifier안) 제거 /
필드명을 사람 말로 / 설명을 결과 중심으로 / 의미 없던 4번째 옵션 삭제 / 영어 라벨 한글화.
