Claude Code의 기계어와 내부 용어의 남발, 안 좋은 가독성.. 지겨우셨나요?   
한국인이 읽기에 적합하지 않은 클로드의 답변을 교정하기 위해, korean-tone을 만들어버렸습니다.

계획·구현 설명, 리뷰, 체크리스트, 연구노트, 선택지의 딱딱한 번역투를 걷어내되 코드와
정확성은 그대로 둡니다.

## ✍️ 이렇게 바뀝니다

### 1. 기술 용어는 지우지 않고 뜻을 풀어 씁니다

```diff
- handler가 stub이었다.
+ handler는 웹훅만 받고 저장하지 않았어요. 함수의 뼈대만 있고 실제 처리가 빠져 있었어요.
```

용어를 다른 말로 바꾸는 것이 아니라, 남겨둔 채 뜻을 한 문장 덧붙입니다.

### 2. 코드에서 찾아야 할 이름은 건드리지 않습니다

```diff
- client_id가 틀렸습니다.
+ client_id가 잘못됐어요. 인스타 전용 앱 ID가 들어갈 자리에 메타 앱 ID를 썼어요.
```

`client_id`는 그대로 남습니다. **저장소에서 다시 찾아야 할 이름(함수·파일·필드·커밋)은
좌표이므로 바꾸지 않습니다.** 이를 "고객 식별자"로 옮기면 사용자가 실제 코드를 찾기
어려워집니다.

### 3. 내부 작업 용어는 답변에서 걷어냅니다

```diff
- [충돌 A] OCR 품질 게이트를 어떻게 처리할까요?
-   (현재: 'acceptable verbatim quality' — 측정 불가 지적)
+ AI가 손글씨를 잘 읽는지 언제 확인할까요?

- 온톨로지를 어떻게 고칠까요? (QA: auth_provider 누락 지적)
+ 데이터 구조를 정리할까요?

- 수렴 제안 2건(인젝션 한 줄 제약 + 디자인 육안 승인 기준)을 적용할까요?
+ 추가 지침은 한 줄로 제한하고, 디자인은 결과물을 직접 본 뒤 승인하도록 할까요?
```

`수렴 제안`, `AC7`, `이터레이션` 같은 말은 Claude가 작업을 관리하려고 쓰는 표현입니다.
사용자의 결정에 필요하지 않다면 답변에 드러내지 않습니다. 다만 내용을 줄이지는 않아요.

### 4. 대시로 잇지 않고 끊어 씁니다

```diff
- **재시도 정책** — 3회까지 지수 백오프로 재시도하며, 그 뒤에는 DLQ로 보냅니다.
+ **재시도 정책**: 3회까지 지수 백오프로 재시도하고, 그 뒤에는 DLQ로 보냅니다.

- 마이그레이션은 두 단계입니다 — 먼저 컬럼을 추가하고, 배포 뒤에 백필합니다.
+ 마이그레이션은 두 단계입니다. 먼저 컬럼을 추가하고, 배포한 뒤에 백필합니다.
```

영어 글쓰기의 em dash 습관이 그대로 넘어온 자리입니다. 라벨 뒤에는 콜론을 쓰고, 문장을
잇는 자리에서는 문장을 끊습니다. 표나 목록의 구분자로 쓰는 대시는 그대로 둡니다.

한 문단에 사실을 서너 개 담았을 때도 끊어 줍니다.

```diff
- 캐시는 1시간 유지되고 이미지 URL 수명도 1시간이라 둘이 겹치면 만료된 주소를 내려주게 되는데, 이때 브라우저는 403을 받습니다.
+ 캐시는 1시간 유지되는데, 이미지 URL 수명도 1시간입니다.
+ 둘이 겹치면 만료된 주소를 내려주고, 브라우저는 403을 받습니다.
```

### 5. 기본적인 번역투도 함께 걷어냅니다

```diff
- 이 함수에 대해 리팩토링을 진행하겠습니다.
+ 이 함수를 리팩토링할게요.

- 입력값 검증이 수행되며, 수정이 이루어졌습니다.
+ 여기서 입력값을 검증했고, 문제도 고쳤어요.
```

## ⚙️ 스킬과 린터가 함께 작동합니다

스타일 규칙만으로는 모델이 놓친 표현을 모두 잡기 어렵습니다. korean-tone은 작성 규칙과
자동 린터를 함께 제공합니다.

| 구성                         | 역할              | 작동 방식                       |
| -------------------------- | --------------- | --------------------------- |
| **작성 규칙(스킬)**              | 문장을 쓰는 기준을 정합니다 | 한국어 답변과 문서에 규칙을 적용합니다       |
| **자동 점검(`tone-linter` 훅)** | 놓친 표현을 알려줍니다    | 한국어 `.md`를 저장할 때 번역투를 검사합니다 |

린터 규칙은 국립국어원의 번역투 연구, 토스 테크니컬 라이팅 가이드, 이오덕의
『우리글 바로쓰기』를 참고해 정리했습니다.

규칙은 두 등급으로 나눕니다. 기계적으로 판별할 수 있는 것은 `error`로 봅니다.
`~에 의해`, 이중 피동, `~에 있어서`, `그녀` 같은 표현이 여기 듭니다.
문맥과 빈도를 함께 봐야 하는 `~를 통해`, `것이다`, 메타 담화는 `warn`으로 둡니다.

코드 블록, 인라인 코드, URL은 검사하지 않습니다.
파일에 `<!-- tone-lint: off -->`를 넣으면 그 파일은 통째로 건너뜁니다.

린터는 파일 저장을 막지 않습니다. 저장이 끝난 뒤 다듬을 표현만 알려줍니다.

## 📦 설치

### 플러그인으로 설치

Claude Code에서만 동작합니다. 작성 규칙과 함께 `tone-linter` 훅이 등록되어, 한국어 `.md`를
저장할 때마다 번역투를 자동으로 검사합니다. 추가 설정은 없습니다.

```bash
/plugin marketplace add fromshim/korean-tone
/plugin install korean-tone@fromshim
```

### skills.sh로 설치

Claude Code 외에 Codex, Cursor, Antigravity, Amp, Gemini CLI 등 여러 에이전트에 설치됩니다.
작성 규칙만 적용되고 훅은 등록되지 않으므로, 자동 검사를 쓰려면
[`hooks/register-hook.py`](hooks/README.md)를 직접 실행합니다.

```bash
npx skills add fromshim/korean-tone
```

## ⏱️ 언제 동작하나

### 스킬: 대체로 알아서 붙습니다

Claude가 한국어로 계획·구현·리뷰를 설명하거나 문서를 쓸 때 스스로 판단해 적용합니다.
따로 부르지 않아도 됩니다.

원하는 때 직접 부르려면 설치 방식에 따라 이름이 다릅니다.

| 설치 방식     | 호출 이름                      |
| --------- | -------------------------- |
| 플러그인      | `/korean-tone:korean-tone` |
| skills.sh | `/korean-tone`             |

"어투 교정", "말투 자연스럽게", "번역투 고쳐", "이 문서 자연스럽게"처럼 말해도 붙습니다.

### 린터 훅: 조건이 맞을 때만 돕니다

플러그인으로 설치했다면 아래를 **모두** 만족할 때 검사합니다.

- Claude가 `Write` 또는 `Edit`로 파일을 저장했을 때
- 확장자가 `.md`, `.mdx`, `.markdown`일 때
- 저장한 내용에 한글이 있을 때
- 파일에 `<!-- tone-lint: off -->`가 없을 때

검사에서 빼는 것: 코드 블록, 인라인 코드, URL, 링크 주소.
`Edit`은 바뀐 부분만 검사하고, 줄 번호는 파일 기준으로 알려줍니다.

대화로 주고받는 답변은 훅이 보지 않습니다. 파일로 저장된 것만 검사합니다.

## 🧪 평가

규칙을 바꾼 뒤에는 같은 사례로 다시 확인합니다.

- **호출 여부**: [`evals/`](evals)의 질의 10개로, 스킬이 필요할 때만 호출되는지 봅니다.
- **교정 품질**: [`evals/quality-cases.jsonl`](evals/quality-cases.jsonl)의 사례 12개를 [`evals/evaluate_quality.py`](evals/evaluate_quality.py)로 채점합니다. 좌표 보존, 번역투 제거, 과교정을 먼저 거릅니다.
- **사람 검수**: 자연스러움, 정확성, 말투 일치, 과교정 여부는 사람이 1~5점으로 매깁니다. 같은 스크립트의 `--write-review`로 검수표를 만듭니다.

```bash
python3 evals/evaluate_quality.py --outputs <파일>   # 자동 채점
python3 hooks/tone-linter.py --selftest              # 린터 자체 점검
```
