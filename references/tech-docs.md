# 요소별 특화 — 기술 문서·README·가이드

README, 가이드, 설명 섹션처럼 **문단으로 서술하는 기술 문서**를 쓰거나 다듬을 때의 규칙.

핵심 한 줄: **결론 문장을 소제목으로 올리고, 근거는 본문으로 내려라. 소제목만 훑어도 글이 읽히게.**

---

## 규칙 T1. 결론 문장이 소제목이 된다

문단마다 결론(주장) 한 문장을 앞세우고, 그 문장을 **완결형 그대로** 소제목으로 올린다.
근거·부연·수치는 본문 문단으로 내린다. 독자가 소제목만 읽어도 문서의 주장 전체가
잡히고, 궁금한 곳만 본문으로 내려가면 된다.

- 소제목을 명사구로 압축하지 않는다: `### 합계 토큰` ✗ → `### 전부 로드돼도 합계 약 15,500 토큰입니다.` ✓
  (압축하면 1-3 한자어 뭉침으로 돌아간다)
- 소제목 레벨은 상위 섹션 바로 아래 단계로 붙인다 (`##` 섹션 안이면 `###`).
  단계를 건너뛰지 않는다.

```
✗ Claude (문단 나열 — 훑어서는 구조가 안 보임)
  전부 로드되는 극단적인 경우에도 합계 약 15,500 토큰입니다. 참고로 Claude Code
  세션은 시작 직후 시스템 프롬프트와 도구 목록만으로 수만 토큰을 쓰고, 문서를 통째로
  내장한 대형 스킬은 로드 한 번에 30만 토큰을 넘기도 합니다.

  수치는 추정이 아니라 실제 세션의 API 사용량으로 쟀습니다. 스킬 로드 직후 요청에서
  입력 토큰이 약 6,000 늘었고, 한국어 마크다운은 대략 1자당 0.85토큰꼴이었습니다.

✓ 교정 (결론은 소제목, 근거는 본문)
  ### 전부 로드되는 극단적인 경우에도 합계 약 15,500 토큰입니다.

  참고로 Claude Code 세션은 시작 직후 시스템 프롬프트와 도구 목록만으로 수만 토큰을
  쓰고, 문서를 통째로 내장한 대형 스킬은 로드 한 번에 30만 토큰을 넘기도 합니다.

  ### 수치는 추정이 아니라 실제 세션의 API 사용량으로 쟀습니다.

  스킬 로드 직후 요청에서 입력 토큰이 약 6,000 늘었고, 한국어 마크다운은 대략
  1자당 0.85토큰꼴이었습니다.
```

## 규칙 T2. 표·코드 블록은 소제목 없이 그대로 (판단 필요)

표나 코드 블록처럼 그 자체로 구조가 보이는 요소에는 굳이 결론 소제목을 붙이지 않는다.
도입 문장 한 줄이면 충분하다. 모든 문단을 기계적으로 소제목화하면 오히려 목차가
소음이 된다 — 결론이라 부를 만한 주장이 있는 문단에만 쓴다.

## 판단 필요 메모 (예시 1건에서만 관찰)

- 소제목 끝 마침표: 사용자가 문장형 소제목에 마침표를 유지했다. 문장임을 드러내므로 따른다.
- 본문 어미: 문서 기본은 합니다체를 유지하되, 사용자가 일부 문장을 해요체로 푼 사례가
  있다. 강제 규칙으로 굳히지 않고 문서의 기존 어미를 따른다.
