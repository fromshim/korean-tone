# 요소별 특화 — 체크리스트·백로그·해체분석

백로그, 체크리스트, "요소 해체분석", 기능 분해처럼 **항목을 쪼개 나열하는 문서**를 쓰거나
다듬을 때의 규칙. 산문과 달리 개조식을 유지하지만, **압축을 풀고 구조를 살리는** 방향이다.

핵심 한 줄: **한 줄에 몰아넣지 말고, 개념·구조 단위로 줄바꿈해라. 대신 도메인 토큰은 건드리지 마라.**

---

## 규칙 C1. 인라인 ·나열 → 줄바꿈 분해

여러 개념을 중점(·)·슬래시로 한 줄에 촘촘히 붙이지 않는다. 개념 단위로 줄을 바꾸고,
한 줄 안의 동류 항목만 쉼표로 잇는다.

```
✗ Claude
  배경 #fff, 카드 표면 제거 (bg 투명·그림자 off·뒤 스택 hidden·곡률 제거), 리스트 풀블리드, 구분선 최소화

✓ 교정
  배경 #fff
  카드 표면 제거 (bg 투명, 그림자 off, 스택 제거, 곡률 제거)
  구분선 최소화
```

## 규칙 C2. 구조 데이터는 구조대로

행/열/케이스처럼 구조가 있는 정보를 인라인 문장으로 뭉개지 않는다. 행별로 줄을 바꾸고
케이스는 라벨을 붙여 명시한다.

```
✗ Claude
  1열 sender/tag/time (태그 sender 옆 나열), 2-3열 썸네일/내용

✓ 교정
  0열 전체높이: SNS, type
  1행: sender, tag, time
  2행: (댓글)썸네일·title, (DM)내용, (메일)타이틀, (비즈니스)컨텐츠
  3행: (댓글)썸네일·내용, (메일)내용
```

## 규칙 C3. 영어 음차·한자 압축 → 우리말 서술 (도메인 토큰은 유지)

서술어·상태·형용에 쓰인 영어 음차나 한자 조어는 평이한 우리말로 편다. **단, 이름이 곧
정체성인 도메인·기술 토큰은 그대로 둔다.**

| 지양 (음차·압축) | 지향 (우리말) |
|------|------|
| flat **파운데이션** | flat **기반** / 전환 |
| 리스트 **풀블리드** | 리스트 좌우를 모두 채움 |
| 텍스트 **최하계층** | 텍스트는 바닥 계층 위에 존재 |
| 뒤 스택 **hidden** | 스택 제거 |
| 그림자 **off** | (문맥상 유지 가능하나) 그림자 제거 |

유지하는 토큰 예: `flat`, `fill`, `grid`, `breadcrumb`, `truncate`, `thread card`,
`SNS`, `RSP`, `ring`, `#fff` 등. 억지로 우리말화하면 오히려 뜻이 흐려진다.

## 규칙 C4. 제목은 의도만, 스펙·상태는 하위 줄로

체크리스트 항목의 **제목(첫 줄)에는 무엇을 왜 하는지(의도·동작)만** 담는다. 세부 스펙,
반복되는 상태 태그(`(실험 완료)` 등)는 하위 줄이나 별도 상태 표기로 내린다.

```
✗ Claude
  - [ ] flat 파운데이션 확정·편입 (실험 완료)
        배경 #fff, 카드 표면 제거 (...), 리스트 풀블리드, 구분선 최소화

✓ 교정
  - [ ] 카드 flat UI 전환
        배경 #fff
        카드 표면 제거 (bg 투명, 그림자 off, 스택 제거, 곡률 제거, 패딩 제거)
        구분선 최소화
```

## 규칙 C5. 메타 노이즈 정리 (판단 필요)

결정과 의도만 남기고, 본질이 아닌 부연은 걷어내는 편이 읽기 좋다. 다만 이건 문서 목적에
따라 다르니 **판단**한다.

- 걷어내는 편: 유사 서비스 예시("gmail/superhuman 식"), git 기계 히스토리
  ("reset --soft로 결별 재정리") 같은 곁가지.
- **함부로 지우지 말 것**: 근거 링크(`_inbox/scratch/...`), 티켓 번호(`dev #96`),
  날짜 출처(`slack 7/3`)는 추적에 필요하면 남긴다. 사용자가 방향 블록에서 이를 덜어낸
  적은 있으나, 이는 취향이므로 임의 삭제하지 말고 필요 시 확인한다.

## 통짜 예시 (방향 블록 + 항목)

**✗ Claude:**
```
> 방향: 카드 표면 철회 → gmail/superhuman 식 flat 리스트. 텍스트는 최하계층,
> floating 은 버튼만 (iOS 톤). glass 는 버튼 한정으로 축소 검토.

- [ ] flat 파운데이션 확정·편입 (실험 완료)
      배경 #fff, 카드 표면 제거 (bg 투명·그림자 off·뒤 스택 hidden·곡률 제거), 리스트 풀블리드, 구분선 최소화
- [ ] thread card 가로형 레이아웃 재설계 (slack 7/3)
      1열 sender/tag/time (태그 sender 옆 나열), 2-3열 썸네일/내용
```

**✓ 교정:**
```
> 방향: 카드 UI 및 전체적으로 둥근 r값 걷어내기
> 	- 카드 UI → flat 리스트
> 	- iOS 디자인 가이드 참조: 텍스트는 바닥 계층 위에 존재, floating 요소는 버튼만
> 	- glass는 버튼 한정으로 축소 검토

- [ ] 카드 flat UI 전환
      배경 #fff
      카드 표면 제거 (bg 투명, 그림자 off, 스택 제거, 곡률 제거, 패딩 제거)
      구분선 최소화
- [ ] thread card 레이아웃 재설계: 가로 여백을 더 활용하는 방향
      0열 전체높이: SNS, type
      1행: sender, tag, time
      2행: (댓글)썸네일·title, (DM)내용, (메일)타이틀, (비즈니스)컨텐츠
      3행: (댓글)썸네일·내용, (메일)내용
```

바뀐 것: 방향은 한 줄 요약 + 중첩 불릿으로 분해 / 제목은 의도만 / 인라인 ·나열은 줄바꿈 /
구조는 행·케이스로 명시 / 영어 음차·한자 압축은 우리말로.
